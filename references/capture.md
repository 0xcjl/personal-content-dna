# 采集、确认与持续积累

## 采集什么

有新增信息时记录：本人明确的选择或否决及理由、具体审美修改、观点变化、实验结果、失败与纠正、尚未解决的问题。一个事件的多轮对话合成一张卡。普通进度、工具输出、AI 单方面提议和重复要求通常不新增卡。

优先引用允许范围内的本人原话。当前可见消息没有稳定 ID 时，保留会话标题/日期可用信息、可检索的短原句及核对日期；事件时间未知就标未知，不把采集日当发生日。本地资料用路径与章节/行号；公开仓库尽量用提交或文件固定链接，无法获取时注明分支与核对日期。

GitHub 先查允许的 README、相关改动与探索记录，识别上游、协作者和实际分工。由作品声明引出的问题先记为待补；不能根据代码替本人编造设计动机。只读回文档不等于运行验证。

## 库结构与索引

采用 Markdown 卡片和 `index.csv`。推荐卡片置于 `cards/`，表达规则置于 `style/`；路径已有其他约定时沿用现有结构。

索引字段：

```text
id,kind,title,path,status,public_use,source_type,source_locator,checked_at
```

- `kind` 为 `material` 或 `style_rule`；卡片 frontmatter 与索引使用相同值。
- `path` 相对库根目录，必须对应真实文件。
- `source_type` 可为 `user_message`、`public_repo`、`project_record`、`project_rule`、`reference_profile` 或 `feedback`。
- ID 沿用已有规则；新库可用 `PD-日期-序号` 和 `STYLE-序号`，先查已用 ID，保持唯一。
- 索引不放受限原文、隐私详情或凭据；保留安全标题与必要定位。

卡片用 [material-card.md](../assets/material-card.md)，规则用 [style-rule.md](../assets/style-rule.md)。未知字段标未知，不补齐看似合理的事实。

## 状态变更

1. **新候选：**`candidate + pending`，即使本人原话的归属已确认，公开范围仍需对应许可。
2. **可用素材：**本人确认其真实含义、归属和具体公开范围后，`approved + allowed`，写明确认记录。直接本人自述可以作为自述来源，独立验证与否另记。
3. **受限素材：**`restricted`，只保存允许保留的安全信息，不提供给普通写作任务。
4. **需要复核：**结果变化、来源冲突、范围撤回时用 `needs_review`，停止调用相关主张。
5. **历史观点：**用 `historical` 保留旧版本及变化原因。写历史变化时先形成经确认、可公开的当前事件卡。

一次确认可以覆盖明确列出的多张卡、主张或共同范围。本人已经提供公开许可时直接记录，避免重新确认。确认某篇稿件的措辞不自动开放整段来源或授权账号发布。

## 活跃会话中的日常流程

- **探索阶段结束：**先完成主要任务，再从当前范围归并有价值事件，存候选并同步索引。
- **本人补一句判断：**保存原话和针对的事件，保留为候选；事实和公开范围已明确的按已有授权处理。
- **确认素材：**展示卡片关键主张与可用边界，记录本人的纠正或采用。
- **每周归并：**在被要求复盘时查候选、重复卡、观点变化和来源缺口；提出少量值得补齐的事件及读者用途。复盘不自动升级状态。
- **改稿后：**进入写作参考文件的反馈流程，材料新增事实仍按本文件核对。

在其他项目汇总到同一库，调用指令应给出允许的项目/会话范围和素材库目标。不要扫描全部本地会话来弥补未指定的来源。

## 读回核对

核对 ID 与路径唯一、卡片与索引一致、个人原话及 speaker 可追溯、行动与结果有状态、确认记录支撑 `approved + allowed`。已有历史卡不直接覆盖成全新结论；保存变更原因。

向写作阶段只提供当前选题相关、允许使用的卡片摘录及精确路径/版本。需要调用受限原始资料补研究时，由本人指定范围后单独处理。

素材库思路参考 [Nicolas Cole：The Right Way To Write With AI](https://artandbiz.substack.com/p/the-right-way-to-write-with-ai) 与本人的探索素材需求；本流程增加来源、分工、公开范围、状态与反馈规则。
